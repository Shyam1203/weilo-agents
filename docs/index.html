Weilo Agents documentation

Weilo Agents is a private chat app for the pi coding agent. It runs on your own computer, in one Docker container. A small daemon inside that container serves the app, keeps your keys, and runs one pi process for each agent you chat with, each as a Linux user of its own.

What it is

You open the app in a browser on a computer or phone that you have paired. You make agents: each one has a name, instructions, a model and the add-ons it may use. Each agent is one continuous conversation, in messenger style. Behind each chat is a pi --mode rpc process that can read and write files and run shell commands inside the container.

One folder of data

Everything you keep lives in one host folder, ~/.weilo-agents, mounted in the container as /home/node/.pi. Copy it to back up or to move to another machine. See Data and permissions.

Agents are not trusted

An agent can run any shell command. So the design assumes an agent may misbehave and puts the important things (keys, devices, other agents' chats) where its Linux user cannot reach them. See Security model.

No code comments; tests for the rules

The code carries no comments: the reasons behind the design live in these pages. The daemon's rules are type-checked and tested (npm run check, npm test, run by CI), and what only a real install shows is on the release checklist. See Development and the release checklist.

Glossary

Agent
A named assistant you chat with: a profile (agent/profiles/<id>/agent.json) plus one continuous conversation and a folder to work in. Its pi runs as a Linux user of its own. See Agents.
pi
The @earendil-works/pi-coding-agent program (installed in the image from image/pi/package-lock.json). The daemon runs it as pi --mode rpc for each open agent and talks to it with one JSON record per line.
Daemon
The Node program daemon/server.mjs (copied to /app in the image), the container's main process. It runs as root, serves the UI and API, keeps keys and devices, and starts everything else as other users. It uses Node built-ins only.
Profile
An agent's settings file, agent.json: name, model, thinking, instructions, skills, plugins, extensions, disabled bundled extensions, avatar, isolated, trusted, dailyTokens, folder and uid. See The profile.
Workspace
The shared folder workspace/ that you browse and that regular agents share. Each regular agent works in workspace/<folder>/.
Vault
The knowledge vault, knowledge/: Markdown pages the curator writes and agents search with fetch_knowledge. Not part of any prompt.
Curator
A background job (daemon/memory/curator.mjs) that runs pi -p as user 1100 inside the vault, reads new chat messages and files what lasts as vault pages. Off until you choose its model.
Gateway
The daemon's routes that pass a pi's model and plugin requests on with the real secret (daemon/gateway/). A pi only ever holds a key of its own that the daemon made for it.
Sandbox
The second container, weilo-sandbox, where isolated agents and their plugin programs run, each in namespaces of its own with only its own folder. It holds no key. See The sandbox.
Paired device
A browser that entered a one-time pairing code and got a device key as an HttpOnly cookie. Only paired devices can use the app. See Pairing.
Isolated
An agent with only its own folder (isolated/<folder>/): no workspace, memory, skill library or settings tools. Set only by you, in Edit agent > Access. See Kinds of agents.
Trusted
"Always allow its own changes": an agent whose requests to change only its own instructions, thinking or skills apply without a question. Set only by you.
Plugin
An MCP server listed in agent/mcp.json, either a program (a command) or a web address. An agent gets only the plugins its profile names.
Skill
A folder with a SKILL.md in the shared library agent/skills/. An agent loads the skills its profile names (--skill); typing / in the chat offers them.
Extension
A pi extension with a weilo.json manifest that adds tools. Bundled ones (browser, routines) come with the app; added ones are uploaded as a .zip into agent/extensions/.
Routine
Work an agent does on a schedule (once, hourly, daily, weekdays, weekly). Kept in agent/routines.json; a due routine is sent to the agent's chat as a message.
