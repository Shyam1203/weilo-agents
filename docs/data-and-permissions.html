Data and permissions

Every folder the app keeps, with its owner, group and mode as the code sets them, and who reads or writes it. The values come from secure() and the helpers in daemon/users.mjs, makeHome and removeFiles in daemon/agents/agents.mjs, writePiDir in daemon/agents/pidir.mjs, and daemon/agents/uploads.mjs and workspace.mjs.

Linux users and groups

Only the group agents exists in /etc/group (made in the image). The other users are plain numbers given to setpriv, so on the host and in ls -l they show as numbers.

How a regular agent's groups are computed

userOf(agent) in agents.mjs returns {uid, gid: uid, groups} where groups is [2000] for a regular agent and [] for an isolated one.

How regular agents read an isolated agent's folder without changing it: the folder is its user's and its own group's with mode 2775, setgid, and the isolated pi runs with umask 002, so what it makes is 0664 or 2775 in its group. The agent and its plugin programs (in its group) write there; everyone else may only read, and "everyone else" can only be someone who passes through isolated/, which is root:agents 0750: the regular agents and their plugins. An isolated agent is in the sandbox and sees no other isolated folder at all.

How owners and modes are kept right

  • At every start secure() sets the top of each place shown above, and each agent's profile. It does not walk whole trees, except two one-time repairs: the tools volume when its group is not agents, and an isolated folder whose group is not its agent's (made before isolated agents had a group of their own), whose contents are handed to the agent once.
  • When made the folders of an agent are set by makeHome (home 2770 in agents, or 2775 in its own group when isolated; chat 0700; HOME 0700) every time its pi starts, in case you removed one.
  • umask 007 in the daemon and setgid folders mean new files are never readable by everyone and keep the folder's group.
  • Through the folder itself: owners are set on an open handle with O_NOFOLLOW, never through a link an agent may have put in place (link-safe setup). A whole tree (tree() in users.mjs) is changed through the opened folder: chown, chmod and find run on /proc/<pid>/fd/<n>/, so a folder an agent swapped for a link is left alone. An approved skill is written the same way, and a skill folder or SKILL.md that is a link is refused.
  • Moves (to or from isolated) refuse a home that is a link, and hand the whole home to the agent in its new group, setgid on every folder: ug+rwX,o+rX,o-w when isolated, ug+rwX,o-rwx when regular. Its chat and HOME move with it.
  • Not on Linux: when the daemon is not root (a development run), none of this happens and everything runs as the daemon's user.

Browsing the folder from the host

On Linux the files belong to numeric users. Add yourself to group 2000, or use sudo, to browse the workspace. Agents' chats, homes and isolated folders are not group-readable by 2000; use sudo for those.

Migrations

daemon/migrate.mjs, run at every start before anything reads the folder. A folder without weilo.json counts as data version 1. Each step runs once and the version is saved after it; this version's DATA_VERSION is 5. A folder with a higher version stops the start: "The data folder was made by a newer Weilo Agents … Update the app, or restore the folder from a backup."

StepWhat it does
1 → 2Each agent without a folder gets one (its name as a slug, made unique) and a home in the workspace. Older files stay at the top of the workspace, shared.
2 → 3Each agent gets a uid. The workspace and skills go to root:agents with group write; the extensions to the group, read only; the vault to the curator; the chats folder to root; each home to its agent in agents; each chat to its agent alone.
3 → 4Every profile gets explicit isolated: false, trusted: false (unless already true). lastUid is set to the highest of the profiles' uids and of every file owner from 2001 up found in the data folder and the tools volume, so no uid is ever given twice.
4 → 5Each isolated agent's HOME moves from homes/ to isolated-homes/ (the sandbox mounts only the latter), and its folder becomes readable, not writable, for the regular agents (ug+rwX,o+rX,o-w; secure() sets the folder itself to 2775).

Adding a step: raise DATA_VERSION and add STEPS[n] that turns a version-n folder into version n + 1, in the same release (RELEASING.md, invariants).
