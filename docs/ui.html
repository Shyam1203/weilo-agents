The app UI

A React 19 single-page app in ui/, built with Vite, Tailwind 4 and TypeScript. It has no router and no data library: state lives in a few components and one reducer over pi's events. The image holds only the built static files, served by the daemon.

Settings and the agent form are separate chunks, loaded the first time they open (lazy in Workspace.tsx), so the first load is smaller: the main bundle went from 533 KB to 456 KB (gzip 161 KB to 141 KB).

Main areas on a computer

  • Setup (features/setup/): with no agent, the main area (the whole screen on a phone) shows two steps: connect a model (the provider rows of Settings > Providers), then pick a ready-made agent from starters.ts or start from scratch, with the model from recommendedModel (lib/models.ts: what the agents use most, else the newest Sonnet or newest full-size model of the first connected provider). Your name is an optional line there; the welcome pop-up waits until there is an agent. The new agent form takes the same starters and folds everything but name, instructions and model under More options.
  • Problems (Problem.tsx): a failed send, an error reply or "No reply" shows with buttons read from the error (fixesFor): Try again, Change model, Open Providers (401, 403, a bad key or sign-in) or Raise limit (the daily limit; it opens Edit agent at More options). After an agent finishes while the app is hidden, useNotifyOffer offers notifications once.
  • Sidebar (Sidebar.tsx): the name, + New agent, a search of all chats, the agents (avatar, name, Isolated tag, time, newest message or what it is doing, "You have the browser" while you hold its window, an unread dot), then an "Update … is available" button when there is one, Settings, and the mail button for Contact us. Drag to reorder (hold first on a phone; Alt+Up and Alt+Down with the keyboard).
  • Chat (ChatView.tsx): the top bar opens Edit agent from the avatar or the name; the model under the name opens a list of your models to switch to (ModelMenu.tsx, it sends only {model}). It has find in this chat, the bolt for the Actions panel, and the globe for the Browser panel (with a dot while the agent's window is open or you have it). What the agent did between its words is one folded line ("Read 2 files · Ran a command") that opens to each step; show blocks, questions and action lines ("… ran by itself") show as themselves; thinking is not shown. Earlier messages load as you scroll up.
  • Composer (Composer.tsx): text, attachments (files and photos, camera, paste, drop), voice typing, the context meter beside send, and Stop during a run (also in the working pill, and Esc). While the agent works, Enter sends a message for it to read before its next step and Alt+Enter (or the clock button) one for when it finishes; queued messages can be edited or taken back. The draft is kept per agent, ↑ in an empty box brings back your last message, typing anywhere in the chat goes to the box, and an empty chat offers starters (EmptyChat.tsx). The + offers Files and photos, Camera, and Skills and commands (what typing / offers: /compact, /reload, the agent's skills and plugins). While the agent waits for an answer, what you type is the answer. Without a provider it shows "Add a provider to send messages."

Phone and computer

  • Below 768 px wide, the list and the chat are separate screens. Opening a chat or Settings adds a step to the browser history (useBackStep), so the phone's back gesture returns to the list; from the Home Screen on an iPhone a swipe from the left edge does (useEdgeSwipe).
  • Settings on a phone lists the pages first, in four groups, with a hint each ("1 connected", "2 skills"), then a page with a back arrow. On a computer it is a menu on the left and the page on the right; the chat stays mounted behind it, so a draft survives.
  • From 1024 px the actions or browser panel docks to the right of the chat; below that it opens as a sheet.
  • Notifications on an iPhone work only from the app added to the Home Screen (a browser rule).

The agent form and its Access card

  • Avatar, name (with the folder it works in: <folder>/ in the workspace, or isolated/<folder>/), instructions.
  • Model: a provider (only connected ones, plus "+ Add provider"), then one of its enabled models (all, when none is enabled), thinking, and a daily token limit (0 is none; an existing agent shows today's count).
  • Built-in extensions: a switch for each bundled extension (Browser, Actions).
  • Add-ons: Skills, Plugins and Extensions, each a row that says what is on and opens a list of switches, or "Add" that opens Settings when there are none.
  • Access: Isolated ("Runs in a sandbox with only its own folder: no workspace, memory, skill library, settings or keys, and no browser unless you turn it on. Your other agents can read (not change) its folder, search its chat, and learn from what it puts in shared/."; when changed on an existing agent: "Saving moves its folder and restarts it."). Turning it on also switches the browser off in the form. Always allow its own changes ("Changes it asks for to its own instructions, thinking or skills apply without asking you; the chat shows each one. Anything else still asks.").
  • Delete opens a dialog that can keep the chat and the files.

Questions and the approval card

An agent's ask and the daemon's approval questions arrive the same way: an extension_ui_request with select (options) or input (a line of text). AskCard.tsx shows the question in full (scrolling inside the card when long), the options as buttons or a text field, and Skip. The chosen answer stays marked in the chat. A pill above the composer says "Waiting for your answer", number keys 1 to 9 pick an option, and what you type in the message box is the answer.

The answer is POST /api/agents/:id/answer {request, value}; Skip sends no value. An approval card's options are "Create it" or "Change it", and "Don't". A change applied without a question (a trusted agent's) shows as a small line in the chat instead.

An extension runs inside the pi of each agent that uses it, as that agent's Linux user. It cannot read the key files; it can use the agent's provider through the gateway, read and change the agent's files, and reach the network.

How the UI talks to the daemon

  • JSON over fetch, same origin, with the device cookie sent by the browser (HttpOnly, so the app's script never sees it). Every request carries X-Timezone (the browser's time zone) for actions that run by themselves. A 401 with pair: true shows the pairing screen.
  • Live events: one EventSource per open chat on /api/agents/:id/events (useChat.ts). The reducer in conversation.ts folds history (only what the chat shows: user and agent messages without thinking, compaction summaries, and the ask, action and manage_agents results) and pi's events into messages. On exit with an error the stream closes and Try again reopens it; a clean restart reconnects by itself.
  • Polling: the agent list every 2 seconds while an agent works, else every 5, only while the page is visible, with ?seen (which also holds back notifications). The list is set again only when it changed, and reloads asked for together run as one. The browser panel polls (every 3 seconds) only while the tab is visible; the actions panel reads again when the chat says an action changed or ran.
  • Rendering: chat text (Markdown, AgentText, CardText) is memoized, so each message's Markdown is parsed once rather than on every streamed delta (on a 200-exchange chat at 4x CPU slowdown, the longest freeze while streaming fell from 2.3 s to 0.13 s, and idle script time from 4.8 s to about 0 per 10 s).
  • The context meter asks GET …/context after history, each settle and each compaction.
  • The live view: a WebSocket to /api/browser/view, speaking VNC through noVNC.
  • Files: /api/agents/:id/files/<path>, ?view=1 for the preview. Inline code in a reply that names a full path in the workspace or an isolated folder, or a path from the agent's folder with a file kind the preview shows, becomes a button that opens the preview.
  • The service worker ui/public/sw.js shows push notifications, one per agent, and opens the app at that agent on a tap.
  • Development: npm run dev in ui/ proxies /api (WebSockets too) to localhost:3210, the running container (Development).
